About Qwertycoin

QWC mainnet combines RandomX mining with EPoSe service rewards.

Qwertycoin is a new mainnet chain derived from the Monero v0.18.5.1 codebase, with QWC parameters, HF17-era privacy technology, RandomX proof of work, and EPoSe from genesis.

EPoSe v2

RandomX PoW secures the blockchain. EPoSe rewards decentralized network service.

No central Sentinel decides which Service Nodes receive rewards. Chain state and EPoSe rules determine qualification, payee selection, and reward validity.

01

Service activity

Registered Service Nodes provide useful QWC network service during each epoch.

02

Attestations

Deterministically assigned verifier committees check service activity and create signed attestations.

03

Reward rotation

Qualification is finalized before deterministic payee selection can affect service rewards.

EPoSe origin

Thank you, Xecute.

The original EPoSe vision and Qwertycoin service-layer whitepaper work came from Xecute, a historical honorary member of the Qwertycoin project. QWC finally carries that plan forward as a decentralized chain-state implementation.

No central Sentinel decides rewards.Explorer and Sentinel-style tooling can observe and monitor, but consensus derives EPoSe state from the chain. Current mainnet reward split: 90% miner / 10% EPoSe service reward.

Mining

RandomX, not CryptoNight.

Old CryptoNight and old mining pool instructions are legacy material. QWC uses RandomX proof of work with a 120 second block target.

Permissionless PoW

Mining is open to anyone who can run compatible RandomX mining software against a QWC node or pool. Active pool documentation will be linked only after it is verified for v2.

No validator council

QWC is not proof of stake. Service Nodes receive service rewards only through the EPoSe layer; they do not replace proof-of-work block production.

EPoSe FAQ

Short answers for new operators.

Does EPoSe replace mining?

No. RandomX miners still produce blocks and secure the chain. EPoSe adds a service-reward layer for registered infrastructure.

What is an epoch?

An epoch is a fixed block period used by EPoSe to measure and finalize service activity. The current QWC parameter is 720 blocks, roughly 24 hours.

What does qualified mean?

Qualified means a registered Service Node has enough valid attestations in the relevant epoch to become reward-eligible.

Who decides whether a Service Node is qualified?

No central server. Qualification is derived deterministically from QWC chain state and valid EPoSe registration and attestation data.

Do Service Nodes need to stake QWC?

No QWC staking role is defined in the current EPoSe core. Service Nodes register a service identity and admission proof; they are not proof-of-stake validators.

Can one operator run multiple Service Nodes?

The protocol can represent multiple Service Node identities. Admission proof makes cheap identity creation harder, but it is not a promise that one human equals one node.

Why is EPoSe not Proof of Stake?

Service Nodes do not lock stake, produce blocks, or vote on chain history. RandomX proof of work remains responsible for block production and ordering.
